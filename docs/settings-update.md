# 设置与体验更新 · 2026-09-09

## 已实现

2. 中英 i18n：默认中文、顶部即时切换并保存偏好；文件、命令、会话标题、model ID 与原生输出不自动翻译。
3. 端点：HTTP(S) 代理、模型列表拉取、手动 ID、模型别名映射、每会话模型覆盖和不可变快照。
4. 品牌标记：Claude 星芒、OpenAI 结形配 Codex 文本；使用已核验许可的 SVG，不再用 C/随机星星代替品牌。Tab 同时使用彩色前景和浅色底：Claude 橙、Codex 紫、Git 青绿，文件按媒体类型区分；真实会话的 provider 优先于旧布局标记。出处见 third-party-notices.md。
5. 会话：打开/重新打开时自动连接；结束移到需确认的二级菜单。结束后普通 Tab 重挂载与刷新不再自动启动；关闭窗口只关闭视图。
6. 文件树：懒加载级联展开、键盘导航、按工作区记忆；预览按钮可展开祖先并定位文件；筛选只包含已加载条目。
7. 工作区载入历史：官方 Codex app-server / Claude SDK 元数据接口、模糊搜索、导入去重；明确同意沿用原客户端配置后才能载入。不是接管外部进程，也不自动复制账号。
8. 新安装默认在 `~/.agentdock` 初始化，支持 `AGENTDOCK_HOME`；保留已有项目内数据库，不自动迁移或注册常驻服务。
9. 开发链改为 Node.js 24+ / pnpm 10.30.3：workspace、安装、Vite、类型检查、测试与原生历史桥接统一使用 Node；Cargo 保持不变。`.nvmrc` / `.node-version` 和 CI 使用 Node 24，不要求降级已安装的更高版本。旧 Bun 锁文件和版本标记归档在 `docs/toolchain-history/`，仅保留历史，不用于当前安装或运行。
10. 引入宿主机现有配置：在端点配置中选择已有 Codex / Claude Code 配置目录，保存为可复用引用；新会话可选择并沿用原客户端账号、模型、端点、代理和权限，不复制配置/凭证。重复引入去重；可改显示名称、进程级环境变量默认值，或移除引用。原生来源身份及直接端点/模型/权限等字段仍不可改。
11. 复用原生登录上下文：保留目录变量的原始值或 unset 状态。macOS 上实测默认 Claude 已登录、强设同一路径却变成未登录，因此不能只保存 canonical 路径；新增 `config_env` 固定这层语义，默认来源不额外设置 `CLAUDE_CONFIG_DIR`。
12. 刷新错误可读化：网络失败与业务错误分开显示，刷新按钮有进行中状态；恢复后的成功读取可清除旧连接错误，不自动重放创建、保存、提交等请求。
13. 高级环境编辑：端点默认值、新建会话、载入历史及已有会话都提供入口；不显示或持久化整份宿主机环境。运行中的会话只读，保存不会自动停止/重启它。

## Node 开发链与连接修复

```sh
pnpm install --frozen-lockfile
pnpm run dev
pnpm run check
pnpm run build:web
pnpm run init
```

`dev` 启动 Cargo 与 Node Vite；已有后端时只运行 `pnpm run dev:web`，开发入口是 `http://127.0.0.1:5173/`。初始化必须使用 `pnpm run init`，不要误用 pnpm 自身的 `pnpm init`。生产前端构建后仍由 Rust 同源提供页面与 API。

已观察到的“一直连接中”不是原生 Agent 一直未启动：后端会话已 running，直连后端 WebSocket 能握手，但经过 Bun Vite 代理会超时。把 5173 的 Vite 换为 Node 后握手恢复；只修复前端运行链，没有因此重启原 8787 后端或其中的 Agent 进程。这是本机已验证的兼容性问题，不泛化成所有 Bun 项目的结论。

UI 现在分开显示“进程运行中”和“实时流已连接”；WebSocket 握手超过 8 秒会进入明确错误状态并提供手动重连。不会自动重试、启动/停止进程或重放用户输入；手动重新附着时已有的有限终端输出回放机制保持不变。原生历史桥接也默认使用 Node，仍支持 `AGENTDOCK_JS_RUNTIME`，其未设置/为空时兼容旧 `AGENTDOCK_NODE_BIN`。

## 高级环境变量：继承与覆盖

端点配置、新建会话、载入历史中可以展开“高级环境变量”。已有会话通过侧栏设置齿轮或 pane 的会话菜单进入，不需要先打开/启动会话；运行中只读，只有 `stopped` / `failed` 能保存，下次主动启动生效。

- 端点的环境默认值与新会话覆盖合并后，保存为该会话的有效显式映射快照；以后修改端点不改变老会话。编辑已有会话是**完整替换**这份映射，不是部分 PATCH；原端点快照不变。
- 载入历史不填覆盖时省略 `environment`，重复载入保留旧会话配置；显式提交不同映射返回 409，不静默改绑。空对象是明确值，不等同于字段省略。
- 继承的是 **AgentDock 后端进程**的环境，保留原有账号隔离和内部变量过滤；不是浏览器机器、另一个终端的临时 exports、shell alias/function/rc 文件，也无法从历史恢复没有记录的旧变量。不会把宿主机整份环境快照写入数据库或发给 UI。
- `literal` 原样赋值，不展开 `$PATH`、`${NAME}`、`~` 或命令表达式。它是明文本地元数据，不能放密钥。`secret_ref` 只接受 `env:AGENTDOCK_SECRET_NAME`，在后端启动环境中配置引用，直到会话启动才解析，不返回真实值。`unset` 明确从子进程启动环境中移除变量。
- 删除覆盖不等于 `unset`：新会话草稿会重新显露端点默认值；已有会话的完整映射删除条目后，让基础启动环境生效。原生配置文件是否提供其他值，仍按 CLI 自己的优先级决定。环境编辑不写回原生源配置，也不承诺覆盖每一种原生设置。
- 名称匹配 `[A-Za-z_][A-Za-z0-9_]{0,127}`；`HOME`、`USERPROFILE`、`PWD`、`OLDPWD`、`CODEX_HOME`、`CLAUDE_CONFIG_DIR`、`CLAUDECODE` 和所有 `AGENTDOCK_*` 大小写无关地保留。名称含 `TOKEN` / `SECRET` / `PASSWORD` / `PRIVATE_KEY` / `API_KEY` / `AUTHORIZATION`，或代理/base URL 含用户名密码时，不能用 literal，应使用 secret reference（或 unset）。这不是通用密钥识别器，其他普通名称也不要填写秘密。
- 最多 64 项、序列化 JSON 不超过 64 KiB；literal 和解析后的 secret 值不超过 8192 UTF-8 字节且不含 NUL。端点默认值与会话覆盖合并后也检查限制。

可选的交互式 Terminal 仍按 shell 自己的行为加载启动文件；这不等于 AgentDock 从旧终端/历史导入了一份环境快照。

SQLite schema 6 增加环境 JSON 字段，旧记录默认为 `{}`，不移动凭证、不重写旧快照。后端通过 `session_environment` capability 声明支持；旧服务上 UI 禁用相关编辑并说明升级原因，不发送缺失路由或不兼容字段。完整合同见 [API 文档](api.md)。

- 旧 8787 服务有运行中会话，未强制停止。新版后端独立在 8788、状态放在 `.agentdock/preview-v2`；未复制用户账号凭证或把旧运行记录冒充新实例会话。
